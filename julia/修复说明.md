# K+S Julia模型关键错误修复说明

## 问题分析

Julia模型存在**关键的初始化和计算顺序错误**，导致：
- GDP、工资等聚合变量出现NaN（非数字）值
- 100%失业率（0就业）
- 在`firm1_produce!`函数第163行发生`InexactError: Int64(NaN)`崩溃

## 根本原因识别

### 1. **R&D劳动力计算使用错误的时期（关键问题）**

**问题描述**：R&D劳动力需求使用**当期**销售额`S1`而非**滞后期**销售额计算。

**C模型**（`fun_KS_firm1.h`第336行）：
```c
v[1] = VL( "_S1", 1 );  // 上一期销售额（滞后1期）
if ( v[1] > 0 )
    v[0] = v[2] * v[1];  // R&D = nu * S1(t-1)
else
    v[0] = min( CURRENT, v[2] * VL( "_NW1", 1 ) );  // 如果没有销售额则使用净资产
```

**修复前的Julia模型**（`firm1_behavior.jl`）：
```julia
revenue = firm.S1 * firm.p1  # 错误：使用当期S1
L_rd = min(params.nu * revenue / firm.w1, params.L1rdMax * L_prod)
```

**影响**：
- 第一期中，`S1`在`firm1_produce!`被调用前为0
- 这导致`L_rd = 0`，然后`L1d = L_prod + 0`
- 当`L1d`为0或NaN时，计算`firm.L1rd * firm.L1 / max(1, firm.L1d)`会产生NaN
- `floor(Int, NaN)`抛出`InexactError`错误

**修复后的Julia模型**：
```julia
# 在Firm1结构体中添加了S1_prev字段
if firm.S1_prev > 0
    RD = params.nu * firm.S1_prev  # 使用滞后销售额
else
    RD = params.nu * firm.NW1  # 回退到使用净资产
end
RD = max(RD, firm.w1)  # 最小约束
L_rd = ceil(RD / firm.w1)
```

### 2. **劳动力需求计算缺少安全检查**

**问题**：当`L1d`或`firm.B`为0或NaN时，会发生除零和NaN传播。

**修复前**：
```julia
L_prod_actual = firm.L1 - floor(Int, firm.L1rd * firm.L1 / max(1, firm.L1d))
# 问题：如果L1d是NaN，产生NaN，然后floor(Int, NaN)崩溃
```

**修复后**：
```julia
if firm.L1 >= firm.L1d || firm.L1d <= 0
    firm.Q1e = firm.Q1  # 不需要调整
else
    # 带明确检查的安全计算
    if firm.L1d > 0
        L_rd_actual = min(firm.L1rd, firm.L1 * firm.L1rd / firm.L1d)
    else
        L_rd_actual = 0.0
    end
    L_prod_actual = max(0.0, firm.L1 - L_rd_actual)
    # ... 其余计算
end
```

### 3. **劳动力需求中的错误缓冲区**

**问题**：Julia模型在劳动力需求中添加了`theta`缓冲区，但C模型并未使用。

**C模型**（`fun_KS_firm1.h`第394行）：
```c
EQUATION( "_L1d" )
RESULT( V( "_L1dRD" ) + ceil( V( "_Q1" ) / ( V( "_Btau" ) * VS( PARENT, "m1" ) ) ) )
// 没有theta缓冲区！
```

**修复前的Julia模型**：
```julia
firm.L1d = (L_prod + L_rd) * (1 + params.theta)  # 错误
```

**修复后的Julia模型**：
```julia
firm.L1d = L_prod + L_rd  # 正确 - 无缓冲区
```

同样的问题也存在于`firm2_compute_labor_demand!` - 已修复。

### 4. **缺少上期销售额跟踪**

**问题**：Julia模型没有机制跟踪滞后变量如`S1(t-1)`。

**解决方案**：在`Firm1`结构体中添加`S1_prev::Float64`字段，并在`agent_step!`中更新：
```julia
function agent_step!(agent::Firm1, model)
    agent.age += 1
    agent.S1_prev = agent.S1  # 保存上期销售额
    # ...
end
```

### 5. **初始化不完整**

**问题**：企业创建时`S1 = 0.0`，意味着第一次R&D计算没有基础。

**解决方案**：用预期初始销售额初始化企业：
```julia
S1 = D10 * p10,  # 预期初始销售额
S1_prev = D10 * p10,  # 用于R&D计算
```

## 修改的文件

1. **types.jl**
   - 在`Firm1`结构体中添加了`S1_prev::Float64`字段

2. **firm1_behavior.jl**
   - 修复`firm1_compute_labor_demand!`使用`S1_prev`而非`S1`
   - 添加最小R&D约束（`max(RD, firm.w1)`）
   - 修复`firm1_produce!`以避免`floor(Int, NaN)`错误
   - 添加除零安全检查

3. **firm2_behavior.jl**
   - 从`firm2_compute_labor_demand!`中移除错误的`theta`缓冲区

4. **scheduling.jl**
   - 更新`agent_step!(agent::Firm1, model)`以保存`S1_prev`
   - 更新`create_entrant_firm1!`以初始化`S1`和`S1_prev`

5. **initialization.jl**
   - 为所有Firm1代理初始化`S1`和`S1_prev`

## 关键修复总结

### 已修复的关键错误：
1. **R&D计算**：从使用当期`S1`改为滞后`S1_prev`
2. **劳动力需求**：从两个部门移除错误的`theta`缓冲区
3. **NaN安全性**：添加检查以防止`floor(Int, NaN)`崩溃
4. **初始化**：正确初始化所有企业的`S1`和`S1_prev`
5. **最小R&D**：添加约束R&D >= 1个工人工资
